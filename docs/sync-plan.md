# План: синхронизация между устройствами

mdpass сам синхронизирует хранилище с облаком через API облака. Папка клиента облака
(YandexDisk, Google Drive) не нужна. Облаков будет несколько: каждое — сменный
«транспорт» за общим интерфейсом, а слияние и вся логика синхронизации от облака
не зависят.

Хранилище по-прежнему лежит локальным файлом там, где его создали: с ним работают
офлайн и открывают без сети. Облако — место, с которым этот файл синхронизируется.

## Решения

- **Трёхстороннее слияние.** База — общий предок, «моё» — документ в приложении,
  «их» — версия из облака (или файл, изменённый на диске). Результат строится из
  «их»: записи, которых я не менял, остаются байт в байт. Мои изменения
  переигрываются поверх операциями `Document`.
- **Точность до поля.** Конфликт — только если одно поле изменили с двух сторон
  по-разному. Теги сливаются как множество. Избранное — моё, без конфликта.
- **Удаление против правки — конфликт.** Ничего не пропадает молча.
- **Конфликт до окна выбора — «оставить обе»:** моя версия рядом с пометкой
  «(копия с этого устройства)».
- **Записи сопоставляются без id в файле:** раздел и название → только название
  (перенесли) → тот же раздел и похожие поля (переименовали).
- **Версия файла — скрытая строка** после метки формата:
  `<!-- mdpass-sync rev=<id> parents=<id>,<id>,… -->`. По ней видно, что чужая
  запись затёрла мою версию (у облаков нет записи «только если не меняли»).
- **Облако — интерфейс `CloudStore`** в ядре: узнать версию файла в облаке,
  скачать, загрузить. Версия — непрозрачная строка от облака (хеш, ETag, номер
  ревизии). Всё остальное — общий движок синхронизации.
- **Доступ — только к папке приложения**, где облако это позволяет (Яндекс:
  `cloud_api:disk.app_folder`, Google: `drive.appdata` или `drive.file`).
- **Токены — в системном хранилище паролей** (Windows Credential Manager, Связка
  ключей macOS, Secret Service в Linux; крейт `keyring`). Не в настройках,
  не в коде, не в файле хранилища.
- **Вход — своим OAuth-токеном**: пользователь получает его на странице облака сам
  (там же регистрирует своё приложение) и вводит в настройках вместе с Client ID.
  mdpass не регистрирует общее приложение и не ходит за кодом сам: без выделенного
  сервера для секрета приложения device flow для публичного клиента не держится
  надёжно, а свой токен работает везде, в том числе на телефоне.
- **В сеть ходит только Rust-часть** и только к подключённому облаку. Интерфейс
  в сеть не ходит, CSP не меняется. В облако уходит только зашифрованный файл:
  хранилище без шифрования не синхронизируется.

## Синхронизация

Состояние на устройстве для каждого хранилища (в папке данных приложения):
версия файла в облаке, которую видели последней, и сами байты этой версии —
база для слияния. Байты зашифрованы, как хранилище.

1. **Узнать версию в облаке.** Файла нет — загрузить свой.
2. **Версия та же, что видели.** Если локально были правки — загрузить.
3. **Версия другая.** Скачать. Локальных правок нет — взять облачную как есть.
   Есть — слить (база — сохранённая версия), записать локально, загрузить.
4. После загрузки запомнить новую версию и её байты как базу.
5. **Первая синхронизация** при уже существующих файлах с двух сторон: базы нет,
   слияние с пустой базой — одинаковые записи совпадут, разные останутся обе.
6. **Нет сети** — работаем локально, синхронизируем позже.
7. **Пароль в облаке другой** (перешифровали на другом устройстве) — не сливать,
   сообщить: открыть заново с новым паролем.

Когда синхронизировать: при разблокировке, после каждого сохранения (в фоне),
и периодически, пока хранилище открыто.

## Этапы

1. ✅ **Ядро: слияние** — `merge.rs`, тесты и проптесты.
2. ✅ **Ядро: версия файла** — `sync.rs`, строка `mdpass-sync`.
3. ✅ **Ядро и Tauri: слияние при записи** — `Vault::save` сливает изменения файла,
   изменённого вне приложения; окно «Записи изменили на двух устройствах».
4. ✅ **Ядро: движок синхронизации** — `CloudStore`, состояние синхронизации на
   устройстве, шаги выше. Тесты на облаке в памяти: правки с двух устройств,
   гонка при загрузке, первая синхронизация, другой пароль в облаке, нет сети.
5. ✅ **Яндекс Диск** — свой OAuth-токен пользователя (регистрирует приложение
   и получает токен на oauth.yandex.ru сам), REST API: метаданные, скачивание,
   загрузка в `app:/`. HTTP-клиент в Rust (`ureq` + rustls). Токен в `keyring`.
6. ✅ **Tauri и интерфейс** — подключить и отключить облако в настройках, ввод
   Client ID и токена, состояние синхронизации («синхронизировано», «нет сети»,
   «ошибка»), синхронизация в фоне.
7. **Окно конфликтов** — моё / их / обе вместо автоматического «оставить обе».
8. **Документация** — `guide.md`, `SECURITY.md` (сеть, токены, что видит облако),
   `manual-check.md` (два устройства, офлайн, гонка), `CHANGELOG.md`.
9. **Другие облака** — Google Drive (Drive API, папка приложения), потом по запросу:
   Dropbox, OneDrive, WebDAV. Каждое — новая реализация `CloudStore` и вход.

Телефон — потом: ядро без Tauri, движок синхронизации и облака им же и воспользуются.

## Чего пока не делаем

- Порядок разделов и записей при расхождении: остаётся как в «их».
- Текст разделов вне записей: берётся из «их».
- Одновременные переименование и перенос записи: считаются удалением и добавлением.
