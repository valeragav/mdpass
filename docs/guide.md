## Первый запуск

На экране «Создайте хранилище»:

1. **Файл хранилища.** По умолчанию `~/Documents/vault.md.age`. «Сменить» — выбрать другое место.
2. **Защита файла**: надёжное шифрование, слабое или без шифрования (см. [ниже](#защита-файла)).
3. **Мастер-пароль** дважды. Для надёжного шифрования — не короче 8 символов, для слабого — 4.
   Полоска под полем показывает, насколько пароль надёжен.
4. **«Создать хранилище»**.

Там же:

- **«У меня уже есть .md-файл»** — создать хранилище и сразу [импортировать](#импорт-из-markdown) в него открытый файл с паролями.
- **«Открыть существующее хранилище»** — выбрать готовый файл `.md.age` или `.md`.
- **Недавние хранилища** — последние пять открытых файлов, открываются одним кликом.

Мастер-пароль нельзя восстановить. Если его забыть, данные из файла не вернуть.

## Защита файла

| Защита | Файл | Открытие | Подбор пароля |
| --- | --- | --- | --- |
| Надёжное шифрование | `vault.md.age` | около секунды | очень дорогой: scrypt 2^18, 256 МБ памяти на попытку |
| Слабое шифрование | `vault.md.age` | мгновенно | в 64 раза дешевле: scrypt 2^12 |
| Без шифрования | `vault.md` | без пароля | не нужен: файл — обычный текст |

Зашифрованный файл — стандартный [age](https://age-encryption.org): его можно расшифровать
и без mdpass командой `age -d vault.md.age`.

Защиту можно сменить в **Настройки → Безопасность → Защита файла**: сменить пароль, перейти
с надёжного шифрования на слабое и обратно, выключить шифрование или включить его у открытого
файла. Имя файла меняется вместе с защитой: `vault.md` ↔ `vault.md.age`.

Что защищено и что нет, подробно — в [SECURITY.md](SECURITY.md).

## Записи

**Новая запись** — кнопка внизу списка или Ctrl+N. Раздел подставляется сам: тот, на который
нажали в списке, или раздел выбранной записи.

- **Шаблоны**: Сервер, База данных, Сайт, Токен, Пустая — набор полей для начала.
- **Поля** — пары «ключ: значение». Кнопки у поля: сгенерировать пароль, показать, скрывать
  значение (замок), удалить поле.
- **Секретные поля** скрыты точками. Поля `password`, `token`, `secret`, `pin` и похожие
  секретны всегда, любое другое поле можно сделать секретным замком.
- **Генератор** даёт 20 символов без похожих (`l`, `I`, `1`, `o`, `O`, `0`), с буквами обоих
  регистров, цифрами и символами.
- **Теги** — через запятую, **заметка** — свободный текст.

В карточке записи:

- **Показать** — значение секрета видно, пока не нажать «Скрыть».
- **Скопировать** — значение в буфере обмена, через 30 секунд буфер очищается. Скопированное
  не попадает в журнал буфера (Win+V). Поле `ssh` копируется готовой командой `ssh user@host`.
- **Markdown** — как запись выглядит в файле (секреты скрыты, пока их не показали).
- **Редактировать** и **удалить** — удаление спрашивает подтверждение, перед ним делается
  резервная копия.

## Разделы

Разделы — заголовки `#` … `######`, вложенность до шести уровней.

- **Клик по разделу** делает его текущим (новая запись создастся в нём) и показывает
  справа его подразделы и все записи этого раздела с полями, без записей подразделов. Повторный клик
  сворачивает и разворачивает раздел, клик по стрелке слева — сразу.
- **Клик по названию записи** в этом списке открывает саму запись.
- **Перетаскивание мышью:**
  - запись на раздел — в конец этого раздела;
  - запись на верхнюю или нижнюю половину другой записи — перед ней или после неё;
  - раздел на другой раздел — внутрь, со всеми записями и подразделами;
  - раздел на верхнюю треть другого раздела — перед ним, на том же уровне;
  - в зону внизу списка — на верхний уровень.
- Раздел, из которого ушла последняя запись, исчезает.

## Поиск и теги

Поиск ищет по названию, разделу, тегам и обычным полям. Значения секретных полей в поиске
не участвуют. Кнопки тегов над списком фильтруют записи по тегу. Пока идёт поиск, все
разделы раскрыты. Если тегов больше, чем помещается в две строки, остальные раскрывает
кнопка «Все теги».

## Формат файла

Хранилище — обычный Markdown:

```markdown
<!-- mdpass:1 -->

# work
## server
**vps1 (инфра)**
ssh: deploy@203.0.113.10
password: ••••
pin_hint!: ••••
note: первая строка
  вторая строка
tags: [work], [prod]
```

| Строка | Что это |
| --- | --- |
| `<!-- mdpass:1 -->` | метка версии формата, в редакторах Markdown не видна |
| `#` … `######` | раздел |
| `**название**` | запись: вся строка жирным, с начала строки |
| `ключ: значение` | поле |
| `ключ!: значение` | секретное поле с необычным именем |
| строка с отступом в два пробела | продолжение значения предыдущего поля |
| `tags: [a], [b]` | теги |

Записи до первого заголовка лежат на верхнем уровне. Строки внутри записи, которые не
похожи на поле, сохраняются как есть. Если файл не менялся, приложение не меняет в нём ни
байта: ручные правки не теряются.

## Резервные копии

- **Когда:** перед каждой записью файла — добавление, правка, удаление, перемещение,
  импорт, смена защиты, восстановление.
- **Что:** точная копия файла до записи, защищённая так же, как файл в тот момент.
  В имени копии только время и действие, названий записей там нет.
- **Сколько:** 30 последних, старые удаляются сами. Меняется в **Настройки → Файл и копии**
  (10, 30 или 100), там же копии можно выключить.
- **Где:** в папке приложения, отдельно от хранилища (см. [ниже](#где-лежат-данные)).

**Восстановить:** Настройки → Файл и копии → «Открыть резервные копии» → выбрать копию.
Справа видно, что изменится: какие записи вернутся, пропадут или в каких изменятся поля
(без значений). «Восстановить эту копию» — текущая версия перед этим тоже сохраняется
копией, так что восстановление можно отменить.

**Файл повреждён:** на экране ошибки «Восстановить из резервной копии», выбрать копию,
ввести её пароль. Повреждённый файл остаётся рядом как `vault.md.age.damaged-<время>`.

Копия, сделанная до смены пароля, открывается только прежним паролем. Её можно сохранить
отдельным файлом кнопкой «Сохранить как файл…».

## Импорт из Markdown

**«Импортировать .md»** на пустом хранилище или **«У меня уже есть .md-файл»** при первом
запуске. Импорт понимает и старый вид, где записи — заголовки (`### vps1`), и превращает их
в `**vps1**`. Найденные неровности можно исправить или оставить:

- ключ `teg` станет `tags`;
- одинаковые заметки `note1`, `note2` станут одной;
- пустые разделы пропускаются;
- в слитное `ключ:значение` добавится пробел.

Справа видно, как файл ляжет в хранилище. Исходный файл не меняется; после импорта приложение
предложит удалить его: пароли в нём лежат открытым текстом.

## Настройки

**Безопасность:** автоблокировка (1, 5, 15, 30 минут или никогда), очистка буфера
(15, 30, 60 секунд или не очищать), блокировка при сворачивании окна, защита файла.

**Файл и копии:** путь к хранилищу, «Переименовать…», «Показать в папке», резервные копии
(включить, сколько хранить, где лежат, открыть список).

**Внешний вид:** тёмная, светлая или как в системе тема, акцентный цвет, размер текста в записях.

## Горячие клавиши

| Где | Клавиши | Что делает |
| --- | --- | --- |
| Главное окно | Ctrl+F | поиск |
| Главное окно | Ctrl+N | новая запись |
| Главное окно | Ctrl+L | заблокировать |
| Список записей | ↑ ↓, Home, End | выбрать запись или раздел |
| Список записей | → или Enter | перейти к полям записи или в список раздела справа (свёрнутый раздел раскроется) |
| Список записей | ← | свернуть раздел или перейти к разделу выше |
| Список записей | ↑ на первой строке | перейти в поиск; ↓ из поиска — обратно в список |
| Поля записи или раздела | ↑ ↓, Home, End | выбрать поле, оно подсвечивается |
| Поля записи или раздела | Ctrl+C или Enter | скопировать поле |
| Поля записи или раздела | Пробел | показать или скрыть секрет |
| Поля записи или раздела | ← или Esc | вернуться в список |
| Список раздела | Enter или → на подразделе или названии записи | открыть его |
| Редактор | Ctrl+S | сохранить |
| Редактор | Esc | назад (с вопросом, если есть правки) |

На macOS вместо Ctrl — Cmd. Работает и в русской раскладке.

## Где лежат данные

| Что | Windows |
| --- | --- |
| Хранилище | где вы его создали |
| Резервные копии | `%LOCALAPPDATA%\io.github.valeragav.mdpass\backups\<файл>-<хеш пути>\` |
| Настройки | `%APPDATA%\io.github.valeragav.mdpass\config.json` |
| Журнал ошибок | `%LOCALAPPDATA%\io.github.valeragav.mdpass\logs\mdpass.log` |

На macOS и Linux — в стандартных папках приложений (`~/Library/Application Support/…`,
`~/.local/share/…`, `~/.config/…`). Настройки и журнал секретов не содержат.

## Вопросы и проблемы

**Забыл мастер-пароль.** Восстановить нельзя. Если остались копии, сделанные до смены
пароля, — они открываются прежним паролем.

**«Файл изменён вне приложения».** Файл поменяла синхронизация (Dropbox, OneDrive) или
вторая копия mdpass. Последнее изменение не записано, чтобы не затереть чужие правки.
«Перечитать файл» загрузит свежую версию, после этого повторите изменение.

**«Файл повреждён».** Проверка целостности не прошла: файл обрезан или изменён. Это не
неверный пароль. Восстановите его из резервной копии.

**«Файл записан более новой версией mdpass».** Обновите приложение: старая версия могла бы
испортить файл нового формата.

**Приложение заблокировалось само.** Сработала автоблокировка или окно свернули. Время и
поведение меняются в настройках безопасности.
